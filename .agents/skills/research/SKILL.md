# Research

Research 解决的是：**当答案依赖外部、最新、会变化、陌生或需要可追溯证据的事实时，取得足够可靠的当前证据再回答。**

默认不是搜得越多越好，而是用最少充分的高质量来源证明关键结论。搜索结果、摘要和聚合页面主要用于发现来源，不自动等于最终证据。

核心链路：定义研究问题和时效范围 → 确定关键 claim → 搜索当前资料 → 追到一手来源 / source owner → 核日期/版本/范围 → 必要时交叉验证 → 区分事实/分析/未验证 → 证据充分后停止。

## 1. 默认使用最新可得资料

除非用户**明确要求历史**资料、指定截止时间、要求离线/禁止联网，或只允许其提供材料，否则：
- 对会变化的产品、模型、公司、职位、价格、标准、法规、API、框架、依赖、新闻、财报、市场、政策、研究进展等，优先取得**当前最新可得且适用于问题**的资料；
- “最新”要核事件时间、版本、发布日期/更新时间、生效日期和适用对象，不只看网页发布日期；
- 无法联网或工具不可用时明确限制，不用模型记忆冒充当前证据；
- 指定历史截止时间时把它当硬范围，不用今天的信息回填当时未知事实。

详见 当前场景所需完整约束 和 当前场景所需完整约束。

## 2. 一手来源优先，claim 追到 source owner

通常优先：官方文档/源码/标准/法规监管原文/公司原始披露或财报/论文原文/第一方 API 数据 → 权威独立研究 → 高质量新闻专业媒体 → 社区讨论和个人经验。来源必须匹配问题；研究真实体验时社区一手经历可以是合适证据。

**不要停在搜索结果。** 标题、snippet、AI 摘要、聚合转载只做导航；重要 claim 打开并核原始上下文。详见 当前场景所需完整约束。

## 3. 证据不足时降低结论，不补故事

多来源一致不等于独立。来源冲突先比较日期、版本、定义、样本、适用范围和原始证据。找不到可靠证据就明确写**证据不足**或无法验证，不编造链接、引用、数字或确定性。引用尽量贴近支持的 claim。详见 当前场景所需完整约束。

## 4. Research 停止条件

当关键结论已有足够高质量、适用、可追溯证据，重大冲突已经解释/标记，且**继续检索**预计不会实质改变结论、边界或行动时停止。不要为了全面或多几个链接无边界研究。

## 5. 与分析和工程任务组合

Research 负责外部 Evidence；Analysis 负责基于 Evidence 做第一性原理解释、因果、方案和决策。两者可组合，但搜到资料不等于完成判断。工程实现、测试、审查、文档和设计仍回到项目专业流程。

## 6. 完成输出

按需给直接结论、关键事实及来源、时间/版本/范围、必要分析、冲突或证据不足和下一步。证据足够时不附带冗长研究过程；用户要求深度报告时再展开。

## 面向用户的项目表达

向用户说明当前任务计划、进展、分工或结果时，用户明确提供的项目术语、计划和决定照常保留，并直接描述当前项目事实、工程动作、验证与真实状态。治理能力或规则的内部名称只服务执行，不把这些名称转写成用户可见的任务步骤、分工或计划；需要说明过程时，使用对应的项目工程动作表达。
