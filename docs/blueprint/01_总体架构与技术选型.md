# 总体架构与技术选型

本文解释 AIMA_UGC **为什么采用当前架构、主要边界在哪里、当前机器事实怎样映射到这些边界**。精确字段、完整 Schema、OpenAPI、依赖补丁版本和 Provider 私有 JSON 不在本文复制第二份。

开发导航先看 [`docs/01_代码结构与修改导航.md`](../01_代码结构与修改导航.md)；长期不可静默改变的决定看 [`docs/blueprint/07_技术决策与实施门禁.md`](07_技术决策与实施门禁.md)。

## 1. 核心架构：模块化单体 + 独立运行进程

当前系统采用单仓**模块化单体**。业务模块在同一代码仓库中，通过 Domain/Service/Contract/Repository/Table Owner 隔离变化；真正需要独立生命周期的运行职责拆为四个 Python 进程：

| 进程 | 入口 | 职责 |
| --- | --- | --- |
| API | [`backend/src/aima_ugc/entrypoints/api_main.py`](../../backend/src/aima_ugc/entrypoints/api_main.py) | 短 HTTP 查询、参数校验、创建持久任务、下载 Artifact |
| Worker | [`backend/src/aima_ugc/entrypoints/worker_main.py`](../../backend/src/aima_ugc/entrypoints/worker_main.py) | 执行采集、导入、AI、导出等长任务 |
| Scheduler | [`backend/src/aima_ugc/entrypoints/scheduler_main.py`](../../backend/src/aima_ugc/entrypoints/scheduler_main.py) | Plan → Occurrence → Run/Job |
| Migration | [`backend/src/aima_ugc/entrypoints/migrate_main.py`](../../backend/src/aima_ugc/entrypoints/migrate_main.py) | 独立执行 Alembic Schema 升级 |

API 不同步执行分钟级采集/大批量 AI，Scheduler 不直接调用 Provider，Migration 不偷偷塞进 API 启动过程。

当前不拆微服务的原因很直接：主要慢点来自外部 Provider、LLM 和数据库 I/O，而不是 Python 模块内调用；API/Worker/Scheduler 已隔离主要运行风险；单体事务更容易保证业务父事实与 Job 一致提交；当前团队无需承担微服务、消息总线和多数据库运维成本。没有真实性能或组织边界证据时，不引入第二套任务队列、Kafka/Redis、第二业务数据库或 Kubernetes。

## 2. 数据主链：外部格式不成为系统公共语言

```text
Provider / File Reader
→ Raw / Source Artifact
→ Operation / Extractor / Mapper
→ Canonical
→ Relevance / Decision
→ Content Owner
→ PostgreSQL Current / Version / Metric / Coverage
→ Query / Analysis / Export / Report
```

核心原则：

- Raw/Source Artifact 保存外部证据和输入字节；
- Mapper 只负责把外部格式变成系统 Canonical，不查数据库、不做跨批去重；
- Canonical 是跨入口共享的业务语言；
- Content Owner 统一处理业务身份、Current/Version/Metric、字段新鲜度和历史；
- File Import 不伪造 Collection Run/Scope，TikHub 与文件导入只在 Canonical/Content Owner 边界收敛；
- 外部 API 变化优先局限在 Operation/Mapper/Fixture，不向业务层扩散 Provider 私有 JSON。

详细采集与标准化边界见 [`docs/blueprint/02_采集系统与数据标准化.md`](02_采集系统与数据标准化.md)。

## 4. PostgreSQL 是唯一业务事实库

当前业务事实统一进入 PostgreSQL。Schema 只通过 Alembic 演进，业务表有明确 Owner；跨 Owner 原子编排放在 Bootstrap/Service 边界，不允许 Router 或其他模块任意写别人的表。

数据库为什么这样拆、Artifact 与数据库怎样分工，见 [`docs/blueprint/03_数据库与文件存储.md`](03_数据库与文件存储.md)。

## 5. 长任务统一使用 PostgreSQL Durable Job Runtime

正式 Worker Registry 由 [`backend/src/aima_ugc/bootstrap/worker.py`](../../backend/src/aima_ugc/bootstrap/worker.py) 装配。当前注册的持久 Job type 为：

```text
collection.run.v1
ingestion.import-excel.v1
ingestion.import-excel.v2
ingestion.historical-discover.v1
ingestion.historical-snapshot.v1
ingestion.historical-import-chunk.v1
analysis.content-run-plan.v1
analysis.content-label.v1
reporting.content-export-excel.v1
```

`ingestion.import-excel.v1` 仅用于消费 Stage 3 之前已经持久化的 queued/running Import；新单文件 Import 创建 `ingestion.import-excel.v2`，并冻结 Brand/Vehicle Filter Snapshot。三个 `ingestion.historical-*` 是统一 Data Import Campaign 延续的物理 Job 名称；`analysis.content-run-plan.v1` 是 Analysis Run Planner。Lease、Heartbeat、Deadline、Fencing、Retry、Cancel、Reaper 等公共语义由现有 Job Runtime 统一维护，业务模块不自建第二套 queue/runtime。

## 6. Scheduler 只负责调度事实

长期链路：

```text
Collection Plan
→ 计算逻辑 slot
→ Occurrence
→ Run / Scope
→ Job
→ Worker
```

Scheduler 不请求 TikHub、不执行 AI。停机恢复和 `latest_only` 等现行语义见 [`docs/appendix/05_Scheduler调度执行与停机恢复.md`](../appendix/05_Scheduler调度执行与停机恢复.md)。

## 7. 前端：Contract 驱动，不复制后端状态机

HTTP 类型链固定为：

```text
Pydantic HTTP Contract
→ FastAPI OpenAPI
→ contracts/openapi/openapi.json
→ Orval
→ generated client
→ Feature API / Store / Page
```

[`frontend/src/generated/api/`](../../frontend/src/generated/api/) 是生成物，禁止手工修改。页面可以做展示资格和交互校验，但并发、一致性、权限和业务终态仍由后端最终校验。

## 8. Identity：业务身份与企业身份提供方解耦

当前已建立 Provider-neutral `Principal` 与 `administrator/user` 角色语义，管理员写操作由后端校验角色；本地使用 Development Identity Resolver。企业身份尚未真正接入，后续飞书只作为 Identity Adapter，不把 `open_id/union_id` 等 Provider 私有身份扩散为业务主键。

因此必须区分：

```text
Principal/后端角色授权边界
→ 已实现

企业真实登录、Session/Claims 验证、撤销/过期
→ 尚未完成 Production 门禁
```

详见 [`docs/product/03_角色权限与产品状态.md`](../product/03_角色权限与产品状态.md) 和 [`docs/roadmap/02_生产上线实施路线.md`](../roadmap/02_生产上线实施路线.md)。

## 9. 技术基线

长期栈：

- 后端：Python 3.14、FastAPI、Pydantic 2、SQLAlchemy 2、psycopg 3、Alembic、uv、pytest/Ruff/mypy；
- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、ECharts、Vitest/Playwright；
- 数据库：PostgreSQL 18；
- 运行：Docker/Compose + Nginx 前端 Runtime；
- 时间：业务展示/调度使用 Asia/Shanghai，数据库机器时间使用 UTC `timestamptz`。

精确版本只看 [`.python-version`](../../.python-version)、[`.uv-version`](../../.uv-version)、[`pyproject.toml`](../../pyproject.toml)、[`uv.lock`](../../uv.lock)、[`.node-version`](../../.node-version)、[`frontend/package.json`](../../frontend/package.json) 和 [`frontend/package-lock.json`](../../frontend/package-lock.json)。
