# 总体架构与技术选型

本文解释 AIMA_UGC 的长期系统形态：**为什么采用当前架构、主要边界在哪里、哪些机器事实负责证明这些边界。**

精确字段、完整 Schema、完整 Job Registry、OpenAPI、依赖补丁版本和 Provider 私有 JSON 不在 Blueprint 复制第二份。

开发定位先看 [docs/01_代码结构与修改导航.md](../01_代码结构与修改导航.md)；普通任务不能静默改变的长期决定看 [docs/blueprint/07_技术决策与实施门禁.md](07_技术决策与实施门禁.md)。

## 1. 系统形态：模块化单体 + 独立运行进程

AIMA 当前采用单仓模块化单体。业务模块共享代码库和 PostgreSQL 事务边界，但运行职责拆成独立进程：

| 进程 | 入口 | 稳定职责 |
| --- | --- | --- |
| API | [backend/src/aima_ugc/entrypoints/api_main.py](../../backend/src/aima_ugc/entrypoints/api_main.py) | 短查询、校验、冻结请求、创建持久任务、读取结果 |
| Worker | [backend/src/aima_ugc/entrypoints/worker_main.py](../../backend/src/aima_ugc/entrypoints/worker_main.py) | 采集、导入、AI、导出、回填等长任务 |
| Scheduler | [backend/src/aima_ugc/entrypoints/scheduler_main.py](../../backend/src/aima_ugc/entrypoints/scheduler_main.py) | 根据 Plan 产生 Occurrence / Run / Job 调度事实 |
| Migration | [backend/src/aima_ugc/entrypoints/migrate_main.py](../../backend/src/aima_ugc/entrypoints/migrate_main.py) | 独立执行 Alembic Schema 演进 |

当前不主动拆微服务，因为主要慢边界来自外部 Provider、LLM、数据库和大文件 I/O；API/Worker/Scheduler 已隔离主要运行职责；单库事务还能保证业务父事实与 Job 原子建立。

没有真实的性能、隔离、组织或部署证据时，不新增第二任务队列、Kafka/Redis、第二业务数据库或 Kubernetes 复杂度。

## 2. 数据主链：外部格式不成为系统公共语言

~~~text
Provider / File Reader
→ Raw / Source Artifact
→ Operation / Mapper
→ Canonical
→ Resolver / Decision
→ Content Owner
→ PostgreSQL
→ Query / Analysis / Export / Report
~~~

长期原则：

- Raw / Source Artifact 保存外部证据；
- Mapper 只翻译外部事实，不承担数据库去重和业务状态机；
- Canonical 是跨入口共享的数据语言；
- Content Owner 统一处理业务身份、Current / Version / Metric、来源贡献和历史；
- File Import 不伪造 Collection Run / Scope；
- Provider 私有 JSON 尽量停在 Adapter / Fixture 边界。

详细机制见 [docs/blueprint/02_采集系统与数据标准化.md](02_采集系统与数据标准化.md)。

## 4. PostgreSQL 与 Artifact 分工

PostgreSQL 是唯一业务事实库；Raw、输入文件、导出、报告、媒体缓存等大文件字节由 ArtifactStore 承担。

原因不是“数据库不能存文件”，而是业务事务、查询索引和大文件生命周期是两种不同问题。Artifact metadata 与业务引用仍进入 PostgreSQL，文件字节可以独立保留、清理或迁移。

详细见 [docs/blueprint/03_数据库与文件存储.md](03_数据库与文件存储.md)。

## 5. 长任务统一使用 Durable Job Runtime

正式 Worker Registry 的唯一机器事实入口：

- [backend/src/aima_ugc/bootstrap/worker.py](../../backend/src/aima_ugc/bootstrap/worker.py)

Blueprint 不维护完整 Job type 清单。新增、删除或改名 Job 后，Registry 和测试已经能给出精确事实；文档只解释长期机制。

公共 Job Runtime 负责：

- Lease / Heartbeat；
- Deadline；
- Fencing Token；
- Retry / Retryable 分类；
- Cancellation；
- Reaper / 接管；
- 持久 Progress / Result。

采集、导入、Replay、撤销、Analysis、Export、重分类和回填都复用这一 Runtime。业务模块可以定义自己的 Payload、Handler 和父业务事实，但不自建第二套内存队列或恢复语义。

Job 与 HTTP/前端的关系见 [docs/blueprint/04_后端任务API与前端.md](04_后端任务API与前端.md)。

## 8. Identity 与业务角色解耦

AIMA 的业务权限基于 Provider-neutral Principal 和 administrator / user 角色，不把飞书 open_id / union_id 等外部身份直接变成公共业务主键。

Identity Adapter 负责 OAuth、外部用户、用户组与 AIMA Principal 的映射；业务表和授权规则只依赖 AIMA 身份。

当前产品状态见 [docs/product/03_角色权限与产品状态.md](../product/03_角色权限与产品状态.md)；完整 Production 身份/浏览器验收仍看 [docs/roadmap/02_生产上线实施路线.md](../roadmap/02_生产上线实施路线.md)。

## 9. 技术基线

长期技术栈：

- 后端：Python 3.14、FastAPI、Pydantic 2、SQLAlchemy 2、psycopg 3、Alembic、uv；
- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、ECharts；
- 数据库：PostgreSQL 18；
- 运行：Docker / Compose + Nginx；
- 时间：业务展示/调度使用 Asia/Shanghai，数据库机器时间使用 UTC timestamptz。

精确版本只看 [.python-version](../../.python-version)、[.uv-version](../../.uv-version)、[pyproject.toml](../../pyproject.toml)、[uv.lock](../../uv.lock)、[.node-version](../../.node-version)、[frontend/package.json](../../frontend/package.json) 与锁文件。
