# 角色权限与产品状态

## 1. 当前角色模型

后端已经建立 Provider-neutral Principal 边界，当前业务角色只有：

- `administrator`：可以执行管理员专属配置写操作；
- `user`：普通业务用户。

角色与企业身份提供方解耦。业务表和权限规则不以飞书 `open_id`、`union_id` 等 Provider 私有身份作为公共主键。

后端统一身份模型见 [`backend/src/aima_ugc/modules/identity/models.py`](../../backend/src/aima_ugc/modules/identity/models.py)。

## 2. 当前认证状态

当前代码同时支持两种装配：未配置飞书时使用显式 Development Identity Resolver；配置单企业或多企业飞书 Connector 时，使用飞书 OAuth 登录、AIMA 自有 Session 和 Provider-neutral Principal 映射。**代码能力已接入，但仍不能等同于完整企业 Production 认证已经验收。**

当前企业认证链路遵循：

```text
企业身份提供方（当前计划为飞书）
→ OAuth 授权码与飞书用户/用户组校验
→ Identity Adapter
→ Principal
→ 后端 Authorization
```

因此当前状态应准确描述为：

- 角色语义和后端管理员授权边界：**已建立**；
- 管理员前端 Route 守卫：**已建立，但只改善交互**；
- 飞书登录/回调、一次性 state、用户组角色判定、Principal 映射、Session 过期和主动登出撤销：**代码已实现**；
- 会话存续期内对飞书远端撤权/移组的周期复核：**尚未实现**，最迟在默认 8 小时会话过期后重新判定；
- 两家真实企业应用、浏览器回调与普通用户/管理员正反向授权：**仍待生产候选环境正式验收**；
- 对公网或扩大访问范围的完整认证安全验收：**尚未完成**。

Production 前置事项见 [`docs/roadmap/02_生产上线实施路线.md`](../roadmap/02_生产上线实施路线.md)。

## 3. 产品权限原则

1. **前端隐藏/禁用不等于授权。** 所有真正受保护的写操作必须由后端再次校验 Principal。
2. **普通用户不接触 Secret。** Provider/LLM API Key、Secret 路径和内部签名 Key 不能通过普通业务页面或日志暴露。
3. **管理员页面不等于系统管理后台万能入口。** 只有当前 Contract/后端真实支持的配置才能展示和修改。
4. **审计记录业务身份和安全差异，不保存 Secret 原值。**
5. **企业身份接入不能重写业务角色。** 飞书只是 Identity Adapter，不把 Provider 私有字段扩散到业务模块。

## 5. 什么时候需要新增角色或权限

只有出现真实业务职责差异，并且后端需要做不同授权判断时，才新增角色/权限模型。不要因为页面上有不同菜单就提前设计复杂 RBAC，也不要为了接入某个身份提供方把 Provider 的组织结构直接变成业务权限模型。
