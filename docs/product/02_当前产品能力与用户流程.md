# 当前产品能力与用户流程

本文只描述当前已经存在的产品行为。精确字段和状态枚举仍由当前 Contract/代码维护。

## 1. 声音广场

### 用户目标

在一个入口查看已经进入系统的内容，筛选和查看详情，需要时复核相关性、发起 AI 分析或导出结果。

### 当前能力

- 查看声音列表和详情；详情主层展示平台、作者、内容类型、发布时间、业务来源、内容可用状态、AI 结果和互动数据，内部 Content/Attempt/Artifact/Batch/Run 等身份只在“技术详情”追溯；
- 首次进入时直接请求并展示第一页，不等待筛选目录、Taxonomy、计数、导出或任务状态；没有已应用筛选时默认读取最新发布时间并按倒序展示；同一会话命中已加载查询时先立即显示已有页，再在后台用服务端最新第一页替换；
- 文本、平台、品牌、车型、竞争范围、相关性、情感、状态、发布时间、发声类型和两级标签在筛选区直接选择；内容类型只在详情表示内容形态，退出本页面筛选，旧会话和链接里的条件会自动清理，不再隐藏进入列表、计数、AI 或导出请求。一级标签与二级标签均支持多选，只有选择至少一个一级标签后才能选择二级标签，二级候选只来自当前所选一级标签的子项；取消一级标签时，不再属于任何已选一级标签的二级选择会同步清理，不能继续隐藏参与查询。同一标签维度内多选按任一命中，一级与二级两个维度同时存在时按两个维度都满足；平台、相关性和分析状态来自生成 Contract，读模型历史回填期间也可立即使用；品牌与车型来自统一目录，其余 AI 业务下拉值由后端筛选目录提供，不在页面维护平行枚举；当前可见内容仍使用旧分析规则的分类时保留为“历史数据”选项；历史目录仍在后台补齐时页面保持无感并自动刷新目录，不展示同步提示，也不把平台筛选误报为不可用；从旧版链接或会话恢复到无法无损映射为当前父子层级的标签组合时，页面会明确显示“旧版兼容筛选”，继续按旧的一、二级维度 AND 语义执行，不因目录刷新静默删除条件；用户主动重新选择标签并查询后才切换到当前层级规则；
- 点击“查询”后，已应用的筛选与排序在当前浏览器会话内保留；离开页面后返回会自动按同一条件加载，尚未提交的筛选草稿不会改变列表；
- 筛选区下方的数量表示当前已应用筛选命中的全部内容数；页面另行标注当前已加载数，不能用首屏或“加载更多”累积的条数冒充总数。计数失败或尚未完成时只显示对应状态，不阻断已经返回的第一页；
- 按发布时间或作者最近已采集粉丝数进行服务器全量升降序排序；缺失值始终置后，默认按发布时间降序；车型选择复用管理员目录的系列、车型名称及别名，未配置系列的车型仍可选择；
- 点击详情时先用当前列表摘要立即打开抽屉，再独立补齐媒体、来源等详情和一级评论；详情或评论任一失败不会清空另一部分；线程回复只在用户展开对应一级评论后读取，不因打开详情一次性请求所有回复；首屏取得下一页 Cursor 后会安全预取下一页，“加载更多”优先复用该结果；
- 查看 AI 分析是否已完成、是否需要重新分析，并查看 AI 原判和当前有效人工复核结果；
- 在列表和详情查看 Brand Tag/Role、车型所属 Brand、竞争范围，以及 Brand/Vehicle 匹配证据；
- 对当前内容版本做人工相关性、发声类型、情感、标签和车型复核；
- 对明确选择的内容、当前已应用筛选条件命中的全部内容，或数据库当前全部可见 Content Current，显式创建 AI 分析任务；“当前筛选结果”不受列表分页、当前已加载数量或排序影响，未显式勾选内容时默认使用该范围，“全部系统内容”需要用户主动选择；
- 勾选 1～1000 条笔记后通过“评论补采”弹窗补充详情和一级评论，二级回复默认开启且可取消；先预览数量和身份缺口，目标变化时重新确认。显式所选内容不按 AI 相关性再次筛选，运行终态自动刷新本页列表、已打开详情和评论；
- 查看活动 AI 分析任务的进度并取消；新任务的临时服务错误和输出校验失败会自动退避恢复，成功内容不会重复发送。服务连续五分钟不可用或同一条内容连续五分钟未通过校验时停止该任务，并在任务中心说明原因；系统配置或权限错误立即停止。已保存成功结果保留，停止后在途请求的收尾统计继续自动更新；
- 从动态 Column Catalog 选择 Brand、Brand Role、Vehicle 和 Competition 列，创建 Excel 导出任务、查看进度并下载已完成文件。

来源 Batch/Run 等内部标识可以由跨页面深链带入，但普通用户不需要知道 ID 才能使用声音广场；页面不保留“手工输入来源 Batch / Run ID”作为常规筛选方式，也不把 API endpoint、LLM Runtime、Job/Run 等实现语言放在默认业务层。

AI 分析任务区域只在存在排队、处理中或取消中的任务时显示；全部进入终态后隐藏，历史与结果仍可在任务中心查看。

## 2. 采集运行中心

### 用户目标

知道“采集/导入现在运行到哪里”，并从同一业务入口发起一次性采集、补采或数据导入。

### 当前能力

- 查看数据导入、辅助补采与管理员手动历史重筛的业务运行摘要、排队/运行/完成/部分完成/失败/取消状态和处理结果；一次“重筛入库”只显示一条“历史数据重筛”记录，不把后台拆分的多个子任务重复展示；
- 按类型、状态、搜索词和创建日期筛选运行；日期使用与声音广场一致的单日、范围及快捷选择，点击“查询”后生效；自动刷新保留已应用条件和已加载列表范围，窄屏可横向滚动查看全部列；
- 发起当前后端 Capability 允许的一次性采集，并在与“导入数据”一致的居中弹窗中，按北京时间发布时间范围对符合资格的已入库内容发起辅助补采；范围覆盖所有来源，排除无发布时间和当前 AI 明确不相关内容；先预览并确认数量，创建时核验指纹并固定清单，不提供基于已有批次的新建补采入口；
- 从同一辅助补采入口选择小红书、抖音、微博、B站和快手；资格说明区分可直接补采、需解析及不可获取。运行详情显示身份解析、一级评论与回复进度、覆盖和失败原因，完成后可进入声音广场按层级分页查看已入库评论。小红书、抖音已验证的短链可自动解析；快手短链、微博视频链接、B站 `b23.tv` 短链以及微博长文章当前不补采评论，页面保留明确原因；
- 一次性发现和日期补采默认采集全部可访问的一级评论和二级回复，用户可以关闭回复或同时关闭评论与回复；选中内容补采一级固定开启。默认全量可能增加请求、费用和耗时；分页上限或接口限制仍会明确显示采集缺口，不承诺平台未开放的数据。周期计划沿用自己的评论策略；
- 新建辅助补采保留“独立发现新内容”和“基于时间的补采”，并列提供“按账号补采”。可选择五个平台、多个账号及必需的北京时间作品日期，账号 ID 类型以实际 Capability 为准、昵称可空；默认全量一级评论与二级回复。创建前确认账号数量、日期与费用提示，不请求 TikHub 估算作品数量。每账号独立显示解析、作品、评论与回复阶段及完成原因；持续失败账号不阻塞其他账号，结果保留并聚合为部分完成。合法账号作品按身份和日期入库，不要求命中品牌词；报告与工作台沿用既有资格及品牌筛选，AI 统计在用户主动分析后产生。
- 通过单一“导入数据”入口选择本地文件/文件夹或管理员批准的服务器目录；来源选择与“标准导入 / 历史补空”写入策略相互独立，切换来源不会改写用户已选策略；
- Excel 的搜索条件明确显示为“不适用于 Excel 文件导入”，内容过滤可选择全部启用品牌及车型或指定品牌；TikHub Discovery 组合 Keyword Pack Search 与独立 Brand Filter，日期补采按已入库内容发布时间选择范围；旧 Batch/Campaign 补采保持历史任务与接口兼容；
- 创建 Data Import Campaign，完成预检、启动、进度查看、取消、失败重试和冲突查看；运行中弹窗按约 5 秒节奏更新已提交的处理统计与已结算来源项，不等任务终态才展示处理结果；预检按文件独立收敛：合法但没有数据行的 Excel 会作为空来源自动跳过，少量真正预检失败的文件保留失败原因但不阻塞同一 Campaign 中已经正常预检的文件继续导入；正常部分完成后仍存在文件级失败时任务显示为部分失败；处理统计中的冲突行数与明细中的冲突字段条数分别展示，便于定位同一行的多个冲突字段；
- 对已完成且具备精确可逆证据的导入，先查看“撤销影响”，再通过确认对话框执行可审计的“撤销本次导入”；取消确认不会提交，失败后可重试；共享来源仍需要的数据保留，旧导入证据不足时系统明确拒绝自动撤销；
- 失败导入可以从全局任务中心的“处理失败项”直接回到对应 Campaign；
- 成功导入后进入声音广场查看对应内容；来源深链作为新的查询入口，不继承上次会话的其他筛选，以免把已入库内容排除。

运行中心默认使用文件、平台、业务状态、进度和结果等用户语言；空文件显示为“没有数据，已自动跳过”，真正失败的文件显示业务提示，Batch/Campaign/Job/UUID/error code 仅在“技术详情”中追溯。页面只做资格提示和交互收敛，后端仍是最终业务守卫。

历史数据重筛的进度由该次请求下所有持久子任务按实际 Canonical Artifact 数加权汇总，处理结果展示 Canonical 文件数、子任务完成情况，以及读取、命中、过滤、去重、新建记录和处理已有记录统计。“处理已有记录”按输入记录累计，同一内容可能重复出现；撤回重组按不同内容计数。详情使用与数据导入一致的弹窗；运行中可“取消并撤回”，终态可撤回请求可“撤回本次入库”，弹窗继续展示撤回阶段、进度和隐藏、保留、跳过、证据恢复等结果。空历史集合作为 100% 已完成且处理数量为零的请求展示；顶部“处理中 / 今日完成 / 今日任务入库量”按一次重筛请求计数，不按子任务或撤回任务重复累计。最后一项汇总各类任务原有入库计数，包含已有内容处理，不表示当前数据库中的去重内容总数。

采集运行列表按来源类型分别展示计数：单文件导入的“本次处理”含匹配后写入或收敛的行；Data Import Campaign 的“新建/补空/更新”不包含未变行，完整分类在导入详情中查看；采集任务的内容与评论按执行范围分别去重后累计，同一内容跨范围可能重复计数，过滤数指品牌车型过滤。已撤销 Campaign 展示后台实际重组的不同内容数；历史旧版影响预估若漏算，以保留的实际处理事实提示差异，不改写审计记录。

查看补采结果时，本次成功处理的已有内容也会出现；重复补采不会为了建立来源关联而新增内容或业务版本。

## 3. 采集策略

### 用户目标

维护长期自动采集的业务配置，而不是每次手工发起运行。

### 当前能力

- 创建、查看和维护关键词包；支持编辑名称/说明、添加/修改/删除关键词、复制、启停、归档/恢复，并仅在服务端确认从未进入业务历史且无引用时永久删除；
- Keyword Pack 只维护 Provider Search Terms，不再承担全局相关性或车型归属；已经冻结到历史采集运行的词包版本不因后续维护漂移；
- 创建、查看、编辑、复制、启停、归档/恢复周期采集计划；计划分别配置 Keyword Packs 与 `all_active / selected Brands`，修改提升调度版本，历史运行继续解释并只读展示其原冻结配置；只有从未执行且无历史引用的归档计划允许永久删除；
- 根据 Provider Capability 展示当前平台真正支持的搜索配置；
- 点击“新建采集计划”使用共用弹窗，默认 WisersOne，可切换 TikHub。WisersOne 配置计划名称、执行频率和内容过滤品牌，到时下载网站过去24小时 Excel 并自动导入；TikHub 继续配置词包、平台和评论策略。编辑保留计划类型，详情使用抽屉。列表显示类型、采集范围与适用的评论策略；
- 评论策略默认自适应，也可选择采集全部可获取的一级评论和回复。全量可能显著增加 TikHub 请求与费用，当前没有请求预算或金额上限；保存或切换策略只影响后续运行，不自动补采历史内容。完整规则和平台差异见 [docs/blueprint/08_采集策略与平台能力.md](../blueprint/08_采集策略与平台能力.md#10-comment-coverage-如何影响后续刷新)；
- 归档词包/计划退出普通目录和新运行入口，恢复后保持停用；保存计划只修改调度配置，真正执行仍由 Scheduler 在到期时产生运行。

词包新建与编辑使用同一表单，名称、说明和全部关键词在底部一次保存；关键词保留各自的平台、优先级、启停和备注。已启用词包允许追加，修改或移除已有关键词前仍须停用。保存失败全部回滚并保留输入，复制名称可以清空后重填。

计划详情可点击词包查看完整当前配置，包括全部关键词、版本与状态；读取失败可重试，关闭后返回计划。新建、编辑和详情不提供 Discovery Vehicle 选择；车型只通过 Brand Filter Snapshot 参与采集，声音广场仍可按车型查询结果。创建与详情弹层支持 Escape 关闭和返回原入口焦点；紧凑桌面宽度下，词包列表与详情上下排列，长内容不会覆盖相邻操作，计划表格可横向滚动查看全部操作。

## 4. 管理员配置

### 用户目标

集中维护只能由管理员改变、并且会影响全局运行的配置。

当前页面已存在正式 `/admin/configuration` 路由，后端写操作继续执行管理员角色校验；前端路由守卫只用于交互，不替代后端授权。

管理员配置涉及模型、Provider、业务目录和运行配置时，Secret 内容不得作为普通业务字段回显。当前 AI/TikHub Provider 支持用户可理解的“测试连接”。AI 模型容量由系统自动探索，界面只读展示状态、全局目标、历史安全点、成功入库速度和延迟，不再配置人工并发、RPS、Timeout 或 Retry；TikHub 采集仍保留原高级执行参数。容量刷新不会覆盖未保存的表单草稿。历史已使用配置只允许归档，未引用归档配置才可能永久删除，恢复后保持停用且非默认。

测试连接针对已保存的服务配置；表单存在未保存修改时，先保存再测试。测试中的同一配置不能重复发起连接请求，切换配置后旧请求结果不会覆盖当前配置；保存失败保留填写内容，目录读取失败时先重试读取。

“品牌与车型”按品牌目录、品牌详情、品牌识别词、旗下车型的 1:N 心智模型工作；新增或编辑车型使用“车型名称”、所属品牌、系列和识别词，不再要求管理员维护类别；Brand 字段与 Alias 使用 Brand API，车型归属只由 Vehicle API 维护，不再提供“词包关联”或 Brand 编辑页中的第二套车型多选 Owner。同一品牌或车型内大小写、首尾空白、连续空白不同但识别身份相同的词，保存时保留第一次出现的写法并自动去重，页面明确提示已经去重保存，不再把这类可收敛输入显示成 Contract 错误。编辑已有车型时只提交实际变化的字段；保存期间编辑层显示“正在保存…”并禁止通过 Escape、遮罩或其他编辑操作关闭，成功后才使用服务端返回结果更新本地目录并关闭，不等待品牌和车型目录全量刷新，失败则保留当前草稿。

新增或编辑 Brand、Vehicle、Alias 只修改目录，绝不自动创建历史重筛任务。只有管理员在“品牌与车型”页点击“重筛入库”并再次确认，才会触发
Persistent Canonical Replay。后端自动选择全部符合当前来源规则的历史 `canonical-content.v1`，
按每个持久任务最多 100 个 Artifact 拆分并使用 1000 行写入批次排队；多个 Worker 可以并行领取，
实际吞吐仍受可用 Worker、Artifact I/O 和 PostgreSQL 写入能力约束。该操作不会重新上传 Excel、
请求 TikHub 或自动触发 AI；空历史集合会明确提示无需创建任务。创建成功提示会引导管理员到“采集运行中心”查看这一条重筛记录的实时进度、处理结果和问题信息。只有本次全量重筛的全部子任务都成功后，系统才会原子发布该次冻结规则的有效结果：同一 Content 的任一历史 Canonical 命中即可保留，全部未命中才退出声音广场、工作台、导出和后续业务任务；运行中、失败或取消不会发布半完成结果。这里的“退出”是统一业务不可见，不物理删除 Canonical、Raw、Content Version、来源或审计；受理时间之后的正常有效入库可以重新恢复可见。撤回只逆转该请求仍独占的 Content Current、业务可见性和自动 Brand/Vehicle Evidence，并在撤回当前规则快照时恢复最近一次仍有效的成功快照；系统升级前没有精确贡献账本的旧请求不允许猜测撤回。

AI 分析规则以结构化的发声类型、情感和标签编辑为主路径，Prompt 模板放在高级设置；页面初次进入时默认打开当前生效版本，并明确标识“当前生效”与“草稿，尚未生效”。规则按方案分组折叠版本，归档区默认折叠，避免历史提示词持续挤占主要编辑区域。复制只产生新草稿；当前生效规则不能直接归档或删除，非 active 规则必须先归档再删除。删除后该规则从管理员配置和恢复入口退出：从未发布、从未使用的纯草稿会物理删除；曾发布或进入分析历史的规则保留不可变 Version、Prompt 与 Hash，只移除管理资源，保证历史 Analysis Run 仍可复现，同时释放规则名称供后续重新创建。

编辑分析规则后，先保存草稿才能发布；保存成功按服务端返回的新版本更新表单，发布或恢复过程中禁止重复提交，失败保留当前输入。

车型表与操作记录表在内容较宽时只横向滚动表格，标题、编辑入口与分页仍可见。

操作记录默认展示“谁在什么时候对什么做了什么、结果如何”，原始 event/object/request ID 与安全 JSON 只在技术详情查看。当前精确配置项以管理员 Feature、Pydantic Contract 和数据库实现为准，不在产品文档复制字段表。

“报告生成”页签从数据库读取品牌、可选车型及日期范围，不需要上传 Excel。管理员先检查本期/相邻等长上期数量、已有分析数量、真实用户数量、评论和模型配置，再创建异步报告。创建时冻结数据和生成依据；历史显示生成进度、计划重试时间、错误类别、模型配置修订与历史分析规则，支持取消和重试。

生成成功后可下载 Word、统一数据 Excel、Markdown 与可编辑图表。飞书通过独立任务发布，失败不影响下载，重试不重新调用模型。默认保留 60 天，到期后文件下载返回过期提示，报告历史与依据继续保留。开发环境默认 `AIMA_FEISHU_DRY_RUN=true`，页面明确提示真实发布已关闭；显式设为 `false` 并完成飞书配置后才允许发布。具体冻结、恢复及清理机制见 [backend/src/aima_ugc/modules/reporting/README.md](../../backend/src/aima_ugc/modules/reporting/README.md)。

## 5. 工作台

### 用户目标

进入 `/` 后直接看到当前业务范围内的声音流、品牌用户心智、UGC 声量与情感趋势，并能从聚合洞察继续进入声音广场核对原声。

### 当前能力

- 工作台继续使用现有 `/` Route，不建立平行 Dashboard Route；页面实现入口在 [frontend/src/features/workbench/](../../frontend/src/features/workbench/)；
- 首次进入先读取品牌、车型与当前分析规则目录，再恢复当前浏览器会话中已应用的日期和全部筛选，首个模块请求直接使用恢复条件。损坏或不兼容的存储回到默认范围；已失效的目录选择自动清理。没有已保存条件时按品牌 code、名称、别名解析爱玛，默认展示截至昨日的完整 7 个北京时间自然日。重置恢复同一默认范围和爱玛，其他维度清空并保存；存储不可用不阻断页面。声音广场仍使用自己的独立重置规则。选择多个品牌时车型候选取这些品牌的并集，明确提交品牌选择后剔除不再适用的车型；
- 声音流拥有三个卡片共用的单行筛选条，空间不足时横向滚动，顺序为日期、品牌、车型、平台、情感、发声类型、一级标签、二级标签、重置。三个卡片右上角显示同一筛选日期；
- 情感、发声类型、一级/二级标签只从当前 active Analysis Scheme 的 active Taxonomy 读取，页面不维护第二套 AI 枚举；一级、二级标签都支持多选，二级候选只取当前已选一级标签的子项并在父级取消后同步剔除失效选择。工作台深链携带完整一级/二级数组；心智维度钻取覆盖一级为被点击标签，同时保留已应用的二级条件，保持聚合与明细范围一致；
- 所有 AI 派生指标只统计当前 active Analysis Scheme Version 产生的结果。历史 Scheme Result 继续保留审计价值，但不会混入当前工作台口径；
- 正向率只统计当前业务有效 `relevant` 内容，其中“正面”使用 active Taxonomy 中精确的“正面”值；
- 品牌用户心智以 active Taxonomy 中非“无法分类”的一级标签为维度，这些业务一级标签的数量就是用户心智图的多边形边数。分母是当前筛选下全部业务有效相关帖子，分子按每个一级标签的 distinct content_id 计数；同一作者的多帖和缺少作者 ID 的帖子均纳入，同一帖子在多个标签中分别计数，标签占比合计可超过 100%。灰色多层网格、粉色数据面与节点保持，中心按筛选显示单品牌名称、多品牌或全部品牌；
- 心智图与详情、趋势与情感统计在所有合法卡片尺寸内保持左右布局。雷达按实际字体测量标签，随容器变化搜索半径、间距和至少 11px 的字号；当前九个正常一级标签完整单行展示，仅异常长名称在最低可读字号仍无法容纳时省略，完整名称保留在详情及标签提示中。每个一级标签均可点击或用 Tab、Enter、Space 操作；选中标签高亮，右侧同步其占比、正向率、变化、二级心智和原声入口。切换指标及后台刷新保留仍存在的标签选择；
- “较上期”统一使用当前时间范围之前、按北京时间自然日计算的紧邻等长区间；
- 声音流、心智与趋势并发读取且各自返回即更新。心智与趋势按规范化筛选读取 PostgreSQL 持久聚合快照；快照陈旧时立即展示最近成功结果，并由持久 Job 后台更新。首次没有快照时接口立即返回“后台准备中”，不会在 HTTP 请求内同步扫描千万级明细；后台失败保留成功结果、记录失败状态并退避自动重试。“重试”只重新读取对应模块；响应携带当前 Scheme Version、Taxonomy、快照状态、计算时间与数据修订身份，前端发现口径切换时才重新同步三个模块；
- 声音流的多选下拉首次进入保持关闭，打开后按触发器、面板和视口的真实尺寸定位，并支持外部点击、Escape，以及页面或筛选条滚动时关闭；面板自身和声音流等相邻模块的内部滚动不关闭当前下拉。缺少原生 Popover API 时使用同一显式状态回退，不依赖浏览器默认样式。日期确认将起止日期作为一个合法区间提交，反向选择也会排序。任一筛选变更后先清除上一筛选的模块结果，再按同一新条件读取后端；冷筛选保留卡片几何并显示后台准备状态，不把旧筛选数据冒充当前结果；
- 声音流使用与完整筛选和页大小绑定的签名 keyset Cursor，在有界页面和浏览器内存内按发帖时间倒序遍历筛选日期内的全部匹配内容；一页滚动完成后自动读取下一页，末页完成后回到第一页并重新纳入最新内容。每页以首尾相接的重复视觉轨道持续向上滚动；悬停、键盘聚焦、标签页隐藏或系统减少动画时暂停。重复轨道仅用于视觉播放，结果计数仍以真实记录数为准；发帖时间按北京时间展示月日与时分，平台标识与声音广场共用同一组件，作者优先取当前内容版本的真实作者快照，缺失时明确显示“未知作者”；点击任一笔记进入声音广场对应内容详情，跨分页也能直接打开；
- 趋势折线消费后端按日声量，使用平滑粉色折线、渐变面积、淡色点状网格和悬停日期声量提示；日均声量四舍五入为整数展示，图表不在浏览器重算聚合或虚构当天成因；
- AI 分析任务有新结果时，工作台复用全局任务中心已有的 Analysis Run 轮询事实并合并刷新；任务终态再进行一次收口刷新，不按单条打标结果高频刷新整页；
- 工作台普通补读周期为 1 小时，只在可见标签页执行，恢复可见时仅在已过期后补读。首次、筛选、手工重试、AI 新结果和终态仍及时请求；preparing/refreshing 使用独立的有界短轮询跟进，失败可重试。慢请求不叠加，普通补读不重置声音流 Cursor；
- 点击心智“查看用户原声”或趋势“查看当天内容”会带日期、品牌、车型、平台、情感、发声类型、一级和二级标签数组进入声音广场；当天钻取覆盖日期区间，声音流笔记另外携带 Content ID。声音广场以 Route Query 形成完整的新筛选快照，清除旧会话隐藏条件；
- 工作台布局采用显式“编辑工作台”模式。排序只能从排序手柄开始，Resize、显示/隐藏只修改本地草稿；三个模块可在现有 12 列网格内按单列调整为 6–12 列宽、48–160 行高，默认 6×48。声音流承载共用筛选而保持可见，心智和趋势可隐藏；读取旧 4/5 列或隐藏声音流布局时归一化并保留顺序和 revision。“保存完成”一次提交完整布局，“取消”丢弃草稿，revision 乐观并发防止覆盖其他会话；
- 工作台聚合只从 PostgreSQL 的正式 Content/Analysis/Identity 事实重建，不额外调用 LLM，也不引入 Redis、Kafka 或 WebSocket。品牌心智和趋势的最近成功结果以可重建持久快照缓存：投影写入用无锁单调修订序列使快照失效，同一筛选和 Scheme 同时只运行一个重型聚合，连续数据写入合并为当前任务完成后的补算；声音广场投影已属于 active Scheme 时复用其有效值，尚未同步时回退到 active Scheme Result 和人工复核/覆盖，避免用错误口径换取速度；
- 页面普通成功或信息确认统一使用共享瞬时提示，默认 3 秒后自动消失；错误、可操作警告和持续任务进度保持可见，不能套用成功提示的自动隐藏计时器。

声音广场和其他自动刷新入口保留已成功显示的值：后台请求不清空目录、不禁用已可用筛选、不插入推动正文的状态行，成功后原位更新，失败保留并在固定位置提示。同值目录保留对象身份，品牌与车型共用一个带 active/all 隔离和在途去重的目录 Owner；筛选选择器的草稿、搜索与滚动不因刷新重置。列表按 Content ID 更新已有窗口，详情编辑和评论展开状态在后台刷新时保持；新的查询先清除旧查询结果并保留占位几何。AI、导出、导入、报告和任务中心沿用各自原有的短轮询频率。

精确请求/响应字段继续由 [contracts/openapi/openapi.json](../../contracts/openapi/openapi.json) 与 Generated Client 持有，本文不复制 API 字段全集。

## 6. 跨页面任务中心

全局任务中心位于 App Shell，用来聚合现有 AI 分析、采集/导入和数据导出等后台任务状态。它没有独立 `/jobs` 路由，也不代表后端增加了一个“万能任务”业务资源。

任务中心的产品价值是：用户离开原页面后仍能知道后台工作是否完成，并能回到对应业务上下文继续操作。失败的数据导入会提供“处理失败项”入口并直接定位到对应导入任务；普通用户不需要先复制 Campaign/Job ID 再排障。

## 7. 一条典型用户流程

```text
管理员维护品牌、识别词与旗下车型，业务人员准备词包与采集计划
→ Scheduler 产生采集运行，或业务人员手动导入/采集
→ 采集运行中心查看后台状态
→ 数据进入统一 Content
→ 声音广场检索/筛选/查看详情
→ 必要时人工复核相关性
→ 显式创建 AI 打标任务
→ 查看结果
→ 导出 Excel 或进入离线报告流程
```

具体代码入口和修改面见 [`docs/01_代码结构与修改导航.md`](../01_代码结构与修改导航.md) 与 [`frontend/README.md`](../../frontend/README.md)。
