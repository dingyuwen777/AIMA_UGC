# 产品概述与边界

## 1. 产品要解决什么

AIMA_UGC 面向企业内部 UGC 舆情工作，把“多平台内容怎么进入系统、怎么持续保存、怎么筛选查看、怎么做 AI 分析、怎么导出”收敛为一套可追溯流程。

当前产品重点不是做一个通用社媒平台，而是让业务人员能完成：

```text
配置采集范围
→ 发起或等待采集/导入
→ 查看运行状态
→ 在声音广场查询内容
→ 必要时人工复核相关性
→ 显式发起 AI 分析
→ 导出 Excel / 进入离线报告链
```

## 2. 当前正式产品面

当前业务页面包括：

- **声音广场**：统一查看已入库内容和分析结果；
- **采集运行中心**：查看采集/导入运行并发起一次性业务操作；
- **采集策略**：维护 Provider 搜索用关键词包，以及独立选择品牌过滤范围的长期采集计划；
- **管理员配置**：按“品牌目录 → 品牌详情与识别词 → 旗下车型”的单一归属关系维护业务目录，并维护 AI 模型、TikHub、AI 分析规则和操作记录；
- **工作台**：当前为开发中占位，不是已完成 Dashboard。

页面的精确 Route 以 [`frontend/src/app/routes.ts`](../../frontend/src/app/routes.ts) 为准。

## 3. 当前数据来源

正式采集支持小红书、抖音、微博、B站、快手；文件导入与在线采集最终进入统一 Content 事实。业务人员不需要理解 Provider 私有 JSON，系统在入口完成归一化和来源追溯。

“导入数据”当前是统一入口：

- 本地电脑：用户显式选择 `.xlsx` 文件或文件夹；
- 服务器目录：只允许管理员批准的只读目录；
- 写入策略：标准观测或历史补空由用户显式选择，与文件来源相互独立。

详细运行语义属于 [`docs/operations/02_4000万历史迁移与Analysis Run运行手册.md`](../operations/02_4000万历史迁移与Analysis%20Run运行手册.md)，不在产品文档复制内部状态机。

## 4. 产品原则

### 4.1 用户看到业务语义，不暴露工程实现

正常页面优先展示“采集运行、导入、AI 分析、导出、失败原因、可重试”等业务语言。内部 Batch/Run/Job ID 可以作为深链或排障证据存在，但不应成为普通用户必须手工输入、记忆或理解的前置条件。

### 4.2 前端不虚构后端能力

下拉选项、状态、筛选范围、可操作条件和日期等都应来自当前后端事实或明确的前端静态产品规则。没有后端能力时，设计稿不能通过虚构 API 让页面“看起来完成”。

### 4.3 长任务必须可离开页面继续运行

采集、导入、AI 分析和导出使用持久后台任务。页面刷新或切换不能成为任务成败的事实源；全局任务中心只是已有任务 read model 的聚合入口，不创建新的万能 Job 业务域。

### 4.4 AI 由用户显式触发

数据导入不会自动产生隐式模型调用。声音广场中的 Analysis Run 由用户显式创建，失败/取消不会删除以前成功结果。

## 5. 当前明确不是产品承诺的内容

以下内容当前没有因为历史 Stage/讨论被自动批准为 Roadmap：

- 通用 Dashboard / 工作台数据驾驶舱；
- Monitoring / Alert / VOC / Ticket 产品模块；
- Web Report Center；
- Gold Set / 自动模型评测中心；
- 双人审批；
- 个人导出列配置；
- 任意其他只在旧方案中出现、尚未重新批准的功能。

如果以后确认要做，应先形成明确产品需求和可观察验收标准，再进入 [`docs/roadmap/`](../roadmap/) 或 GitHub Issue/Change。
