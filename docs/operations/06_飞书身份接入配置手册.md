# 飞书身份接入配置手册

本手册说明**怎样把一个或多个飞书企业接入 AIMA_UGC，并自证配置正确**。

它只讲"已经存在的飞书登录能力怎样安全配置"。飞书身份能力的架构与安全边界见
[`docs/blueprint/05_日志安全部署与运维.md`](../blueprint/05_日志安全部署与运维.md)；
企业认证的正式验收状态见 [`docs/roadmap/01_生产上线实施路线.md`](../roadmap/01_生产上线实施路线.md)。

## 1. 适用场景与前置条件

适用：本地 Compose、公司服务器或生产候选环境首次接入飞书登录，或新增第二家企业。

前置：

```text
□ 已经有可用的 AIMA_UGC 部署（Compose 能正常起来）
□ 有飞书开放平台的应用管理权限（建应用、配权限、发版）
□ 有飞书管理后台的组织架构权限（建/查用户组 ID）
□ 能确定该站点的对外访问地址（协议、域名或 IP、端口）
```

**必须先确定的两个值**（后面所有地址都依赖它们）：

| 值 | 说明 |
| --- | --- |
| **站点地址** | 用户浏览器实际访问的地址，如 `https://ugc.example.com` 或 `http://192.0.2.10:8080` |
| **企业标识（`code`）** | 每家企业一个短标识，会进 URL。只允许小写字母、数字、连字符，且以字母或数字开头 |

> **站点地址的三个硬要求**：飞书后台登记的重定向 URL、网页应用主页、配置里的 `redirect_uri`
> 必须**协议、域名/IP、端口完全一致**。生产环境必须 HTTPS。

## 2. 飞书开放平台要配什么

**每家企业各自一个自建应用，各自配置，互不共用。** 两家企业共用一个应用是不行的：
`app_id` 是身份空间的一部分，共用会让两家用户身份互相覆盖。

### 2.1 添加「网页应用」能力

开发者后台 → 应用 → 左侧「添加应用能力」→ 找到「网页应用」→ 添加。

### 2.2 开通权限

按本手册的登录与角色判定链路，需要 5 个权限：

| 权限 | 身份类型 | 用途 |
| --- | --- | --- |
| `contact:group:readonly` | **应用身份** | 查用户所属用户组（判角色的依据） |
| `contact:user.base:readonly` | **用户身份** | 取登录用户的姓名等基础信息 |
| `contact:contact.base:readonly` | 应用身份 | 展示部门信息 |
| `contact:user.department:readonly` | 应用身份 | 取用户所属部门 |
| `contact:department.base:readonly` | 应用身份 | 取部门名称 |

> 前 2 个不配，登录或判角色会直接失败；后 3 个只影响部门信息能否展示。
> 部分权限需要额外设置「数据范围」（可访问的部门/成员），按最小必要范围配置。

### 2.3 配置「重定向 URL」

开发者后台 → 应用 → 左侧「安全设置」→「重定向 URL」→ 添加：

```text
<站点地址>/api/v1/auth/feishu/<该企业 code>/callback
```

**必须与 `AIMA_FEISHU_CONNECTORS` 里该家的 `redirect_uri` 逐字一致。**

### 2.4 配置「网页应用主页」

开发者后台 → 应用 → 左侧「网页应用」→ 网页配置：

| 字段 | 填 |
| --- | --- |
| 桌面端主页 | `<站点地址>/login?c=<该企业 code>` |
| 移动端主页 | 同上 |

**为什么带 `?c=`**：它让用户从本企业工作台进入时，登录页直接显示"你正在从【本企业】登录"，
不需要在企业列表里自己选。不带 `?c=` 时登录页会列出全部已配置企业，用户**可能选错企业**，
选错后飞书会以"你没有该应用的使用权限"拒绝（因为账号不属于那家企业）。

**注意**：`?c=` 只影响"选哪家"，用户仍需点一次登录按钮。若希望完全跳过登录页，
主页可直接填 `<站点地址>/api/v1/auth/feishu/<code>/login`，但这会跳过前端页面。

### 2.5 发布

- **正式应用**：改完配置要「创建版本 → 发布」才生效；
- **测试版应用**（使用"测试企业与人员"时）：改完即时生效，无需发版。

## 3. AIMA 侧配置

配置在部署根目录的 `env.local`（本地）或 `env.production`（服务器）中。

### 3.1 单企业装配

一家企业时，填这 4 个变量即可，回调地址**不带企业标识**：

```dotenv
AIMA_FEISHU_APP_ID=<App ID>
AIMA_FEISHU_APP_SECRET_REF=feishu_app_secret
AIMA_FEISHU_ADMIN_GROUP_ID=<管理员用户组 ID>
AIMA_FEISHU_USER_GROUP_ID=<普通用户组 ID>
AIMA_FEISHU_REDIRECT_URI=<站点地址>/api/v1/auth/feishu/callback
```

### 3.2 多企业装配

**两家及以上**用 `AIMA_FEISHU_CONNECTORS`，值是**一整行紧凑 JSON 数组**（不能换行）：

```dotenv
AIMA_FEISHU_CONNECTORS=[{"code":"aaa","display_name":"A 公司","app_id":"cli_aaa","app_secret_ref":"feishu_aaa_secret","admin_group_id":"<管理员组ID>","user_group_id":"<普通组ID>","redirect_uri":"https://ugc.example.com/api/v1/auth/feishu/aaa/callback"},{"code":"bbb","display_name":"B 公司","app_id":"cli_bbb","app_secret_ref":"feishu_bbb_secret","admin_group_id":"<管理员组ID>","user_group_id":"<普通组ID>","redirect_uri":"https://ugc.example.com/api/v1/auth/feishu/bbb/callback"}]
```

字段含义：

| 字段 | 填什么 | 谁定 |
| --- | --- | --- |
| `code` | 企业标识，会进 URL；小写字母/数字/连字符 | 部署方 |
| `display_name` | **登录页上显示的名字**，中文可以 | 部署方 |
| `app_id` | 飞书应用 App ID（「凭证与基础信息」页） | 企业方提供 |
| `app_secret_ref` | **Secret 的文件名**，不是 Secret 内容 | 部署方，每家不同 |
| `admin_group_id` | 管理员用户组 ID | 企业方提供 |
| `user_group_id` | 普通用户组 ID | 企业方提供 |
| `redirect_uri` | `<站点地址>/api/v1/auth/feishu/<该家 code>/callback` | 部署方拼 |

### 3.3 配了多企业后，上方哪些变量还有用

**登录**以 `AIMA_FEISHU_CONNECTORS` 为准。上方的变量分成两类，**不能一并留空**：

| 变量 | 配了多企业后 | 依据 |
| --- | --- | --- |
| `AIMA_FEISHU_ADMIN_GROUP_ID` | **登录不再读**，可留空 | 只在单企业登录装配里使用 |
| `AIMA_FEISHU_USER_GROUP_ID` | **登录不再读**，可留空 | 同上 |
| `AIMA_FEISHU_REDIRECT_URI` | **登录不再读**，可留空 | 同上 |
| **`AIMA_FEISHU_APP_ID`** | ⚠️ **仍是「飞书多维表同步」与「Word 报告发布」的配置** | 这两个能力也读该变量；若本部署使用它们，**必须按它们自己的应用填写** |
| **`AIMA_FEISHU_APP_SECRET_REF`** | ⚠️ **同上** | 同上 |

> **为什么容易踩**：这三个能力（多维表同步 / 报告发布 / 身份登录）共用
> `AIMA_FEISHU_*` 前缀，其中 `AIMA_FEISHU_APP_ID` 与 `AIMA_FEISHU_APP_SECRET_REF`
> 被三者共同读取。配了多企业只改变**登录**的取值来源，
> 不会让同步/报告改用 `AIMA_FEISHU_CONNECTORS`。
>
> **判据**：本部署若不使用同步/报告，这两个变量留空无影响；
> 若使用，则它们必须指向同步/报告自己的应用，且与 `CONNECTORS` 里任何一家的
> `app_id` 关系不受限制（可以是同一应用，也可以是不同应用）。

### 3.4 五条硬约束

违反任意一条，**进程启动时直接报配置错误**，不会静默降级：

| # | 约束 | 违反后果 |
| --- | --- | --- |
| 1 | 每家的 `code` 不能重复 | 后一条覆盖前一条，某家企业静默失效 |
| 2 | 每家的 `app_id` 不能重复 | 两家派生同一身份空间，用户身份互相覆盖 |
| 3 | 每家的 `app_secret_ref` 不能重复 | 两家共用同一份 Secret 文件 |
| 4 | 每家的 `redirect_uri` 必须含 `/feishu/<自己的 code>/callback` | 回调落到别家企业 |
| 5 | 同一家内 `admin_group_id` ≠ `user_group_id` | 角色判定退化为"在组里即管理员" |

## 4. App Secret 落盘

App Secret **不写在环境变量或配置文件里**，而是每家一个文件。

### 4.1 放哪里、叫什么

```text
${AIMA_HOST_ROOT}/shared/provider-secrets/<该家的 app_secret_ref>
```

`AIMA_HOST_ROOT` 是 `env.local` / `env.production` 里的变量（本地默认 `./.runtime/compose`）。

例：两家分别对应

```text
${AIMA_HOST_ROOT}/shared/provider-secrets/feishu_aaa_secret
${AIMA_HOST_ROOT}/shared/provider-secrets/feishu_bbb_secret
```

容器内看到的是 `/run/provider-secrets`（由 `AIMA_EXTERNAL_SECRET_DIR` 指定）。

### 4.2 文件内容

**只放 App Secret 本身**，一行，**末尾不能有换行**、不能有首尾空格。
飞书后台请用「复制」按钮取值，不要手抄（少一个字符会得到 `app secret invalid`）。

### 4.3 Linux / 公司服务器

直接放到 `${AIMA_HOST_ROOT}/shared/provider-secrets/`，权限建议 `640`，
属主为容器内读取该目录的用户。Compose 已把该宿主目录 bind 进容器。

### 4.4 Windows + Docker Desktop 额外一步

Windows 下该目录挂在 **Docker 命名卷** `aima-ugc_windows_provider_secrets` 上，
而不是宿主目录。**只往宿主目录放文件，容器读不到**，必须再同步一次：

```powershell
docker run --rm --user root `
  -v "<宿主 provider-secrets 目录>:/from:ro" `
  -v aima-ugc_windows_provider_secrets:/to `
  aima-ugc-backend:internal-v1a `
  sh -c "cp -f /from/* /to/ && chown 0:11001 /to/* && chmod 640 /to/*"
```

## 5. 生效

环境变量只在容器创建时读入；Secret 文件在进程启动时读。

```bash
docker compose --env-file env.local -f compose.yaml -f compose.windows.yaml \
  up -d --force-recreate api worker scheduler
docker compose --env-file env.local -f compose.yaml -f compose.windows.yaml \
  restart frontend
```

- `--force-recreate` 必须：只 `up -d` 不会重新读取变更后的 env；
- `restart frontend` 必须：nginx 启动时解析一次 `api` 主机名并缓存，
  重建 api 后容器 IP 变化，不重启 frontend 会得到 `502`。

Linux 上不叠加 [`compose.windows.yaml`](../../compose.windows.yaml) 时去掉该 `-f` 参数。

## 6. 验证

按顺序做，任一步失败就不要继续。

### V1 配置是否进入容器

```bash
docker exec aima-ugc-api-1 printenv AIMA_FEISHU_CONNECTORS
```

有输出即已传入；空输出说明没有 `--force-recreate`。

### V2 Secret 文件是否就位

```bash
docker exec aima-ugc-api-1 ls -la /run/provider-secrets/
```

每个 `app_secret_ref` 应各有一个文件。缺文件说明没放，或 Windows 漏了 4.4 步。

### V3 企业列表是否正确

```bash
curl -s http://127.0.0.1:8080/api/v1/auth/connectors
```

预期返回每家一条，只含 `code` 与 `display_name`，**不含密钥、组 ID 或回调地址**：

```json
{"items":[{"code":"aaa","display_name":"A 公司"},{"code":"bbb","display_name":"B 公司"}]}
```

### V4 每家的登录入口是否指向自己的应用（**最关键**）

```bash
for c in aaa bbb; do
  echo "--- $c ---"
  curl -s -D - -o /dev/null "http://127.0.0.1:8080/api/v1/auth/feishu/$c/login" \
    | tr -d '\r' | grep -i '^location'
done
```

**⚠️ 必须用 `curl -s -D - -o /dev/null`（GET 取头），不要用 `curl -sI`** ——
`-I` 发 HEAD 请求，登录路由只接受 GET，会返回 `405`；看到 405 是用错了命令，不是配置错。

预期每家的 `location` 里 `client_id` **等于该企业自己的 App ID**，
`redirect_uri` **含该企业自己的 code**。两家的 `client_id` 相同即为配置串号。

### V5 真实登录

用该企业的飞书账号走完整流程，确认能进入系统并显示正确身份。
若要验证"同一人在两家企业得到两个独立身份"，用同一账号依次从两家入口登录，
数据库 `identity_external_identities` 中应出现两条不同 `connector_id` 的映射。

## 7. 常见报错对照

### 7.1 启动时报配置错误

| 报错片段 | 原因 | 处理 |
| --- | --- | --- |
| `不是合法 JSON` | JSON 语法错（多逗号、少引号、被换行拆断） | 用 JSON 校验器过一遍，确认整行未被折行 |
| `必须是 JSON 数组` | 写成了对象 `{...}` | 外层套方括号 |
| `code='X' 不合法` | `code` 含大写或特殊字符 | 改为小写字母/数字/连字符 |
| `redirect_uri 必须包含 '/feishu/X/callback'` | 回调地址少了企业标识段，或带了别家的 | 改成 `/feishu/<本条 code>/callback` |
| `code 重复` | 两家 `code` 相同 | 改掉其中一个（约束 1） |
| `使用了同一个 app_id` | 两家用同一应用 | 两家各建独立应用（约束 2） |
| `使用了同一个 app_secret_ref` | 两家 Secret 文件名相同 | 改成两个不同文件名（约束 3） |
| `admin_group_id 与 user_group_id 相同` | 同家里两个组 ID 一样 | 建两个独立用户组（约束 5） |
| `缺少非空字符串字段` | 少写字段 | 补齐 7 个字段 |
| `多企业配置不能是空列表` | 写了 `[]` | 要么不写这行，要么至少写一家 |

### 7.2 运行时报错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `app secret invalid` | Secret 值不对（常见：多/少字符，或文件末尾有换行） | 用飞书「复制」重取，确认文件无换行 |
| `SecretFileError` | 文件不存在、权限不对，或 Windows 没同步进卷 | 见 4.2–4.4 |
| 飞书返回 `20071` / `20029` | 飞书后台登记的回调地址与配置不一致 | 逐字符核对 |
| `unknown_connector`（404） | 访问了没配置的 `code` | 检查 `AIMA_FEISHU_CONNECTORS` |
| 登录后进了别家企业 | `redirect_uri` 的 code 与本条不一致 | 见约束 4 |
| `502 Bad Gateway` | 重建 api 后没重启 frontend | 见第 5 节 |
| 改了配置没生效 | 没 `--force-recreate` | 见第 5 节 |
| 用户看到企业列表而非"正在从 X 登录" | 飞书后台「网页应用主页」没配 `?c=` | 见 2.4 |
