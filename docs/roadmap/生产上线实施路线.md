当前仓库已经形成主要业务基础：


当前完整 Production 仍是 **No-Go**。这不是因为核心业务功能尚不存在，而是生产部署、认证授权、Release、Backup/Restore、正式生产验收等长期能力尚未闭环。

公司内网 V1 是更窄的近期里程碑：

```text
公司内部网络使用
不对公网开放
首版不做 Authentication / Authorization
首版不做旧历史数据 Migration
先把当前业务功能稳定运行并部署
```

# 2. 当前执行顺序

2026-08-23 的运行审计确认：Stage 8F 业务前后端已经闭环，但源码环境仍把 PostgreSQL、Secret、Migration、Worker 和大量环境变量的装配责任暴露给开发者。因此在 Internal V1-A 前增加一个小而正式的 Local Dev Bootstrap 单元。

当前顺序：

```text
Stage 8F：前后端业务闭环
→ 已完成
↓
Local Dev Bootstrap：跨平台源码开发启动收口
→ 当前开发单元
↓
Internal V1-A：最小 Docker / Compose / Production Config
↓
Internal V1-B：公司服务器真实部署与业务 Smoke
↓
公司内网 V1 上线
↓
Production Backlog
↓
完整 Production Go-Live
```

Local Dev Bootstrap 不重新设计业务 Contract，也不提前实现生产 Compose。它先把正式 Worker 入口、源码开发配置和开发者使用方式收口，再由 V1-A 容器化同一套运行事实。

# 3. 阶段状态定义

只使用：

```text
已完成
→ 当前代码/Contract/Migration/tests/已合并交付能够证明主要目标闭环

部分完成
→ 已有正式实现，但当前产品仍有明确剩余目标

待实现
→ 目标仍有效，但当前机器事实尚未落地

已被后续决策替代
→ 历史方案不再是当前待办
```

Stage 名称、README 文案、单次 CI 绿色都不能单独作为完成证据。正式单元仍需按 Completion Gate 重新读取上游完成定义。

# 12. Local Dev Bootstrap：跨平台源码开发收口

## 状态：Internal V1-A 前置单元

正式目标：Windows/Linux 源码开发使用同一套两个 Python launcher：

```bash
uv run python scripts/dev/backend.py
```

```bash
uv run python scripts/dev/frontend.py
```

Backend 自动处理：

```text
env.local 首次复制
.runtime 目录
PostgreSQL 18.4 本地容器
随机 DB Password Secret
Cursor Secrets
Alembic upgrade head
TikHub/LLM dev 输入 → 正式 Secret File
TikHub Local Dev Provider Config
正式 Worker
可选 Scheduler
FastAPI
/health/ready
```

Frontend 自动处理：

```text
Node/npm 版本检查
node_modules / package-lock 指纹
必要时 npm ci
Vite dev server
```

关键边界：

```text
env.local
→ 仅本地 launcher 输入
→ Git ignored

正式子进程
→ 继续使用 AIMA_* + Secret File

生产部署
→ 不使用 dev launcher
→ 继续进入 Internal V1-A
```

TikHub/LLM 未配置只 Warning；基础 Excel/Voice Plaza/Export 仍可运行。Scheduler 默认关闭，避免本地残留 Plan 意外产生外部费用。

完成定义和验证见 [`内网V1上线实施计划.md`](内网V1上线实施计划.md)。

# 15. 公司内网 V1 判定

完成 Local Dev Bootstrap + V1-A + V1-B 后，可以定义：

> **AIMA_UGC 公司内网 V1 已上线。**

当前明确允许首版延期：

```text
Authentication / Authorization
Legacy Migration
完整 RPO / RTO
完整协调 Backup/Restore
长期 Retention / Capacity / Soak 数字
完整不可变 Release / SBOM / 签名
```

这不是删除长期目标，只是不让它们继续阻塞内网首版。

# 16. Production Backlog：认证与授权

系统暴露到更广网络、需要多用户权限或敏感数据分级前，必须建立真正的后端 Authorization。

长期边界：

```text
External Identity Provider
→ Authentication Adapter
→ Principal / AuthContext
→ Authorization
→ Business Service
```

不能用前端隐藏按钮、内网位置或单纯 Nginx 限制替代后端授权。

---

# 18. Production Backlog：Backup / Restore / DR

后续需要正式冻结：

```text
RPO
RTO
maintenance / write barrier
PostgreSQL + Artifact coordinated backup set
restore verification
rollback 与 Schema/Artifact 一致性
```

不能只备 PostgreSQL 而丢失 Artifact，也不能只复制 Artifact 而没有匹配数据库快照。

# 20. 新会话如何判断下一步

每次仍先按 `AGENTS.md` 读取当前 `main` 机器事实。

顺序判断：

```text
Local Dev Bootstrap 未闭环
→ 先完成它

Local Dev Bootstrap 已闭环、V1-A 未完成
→ 做 V1-A

V1-A 已完成
→ 做 V1-B 公司服务器验收

V1-B 已完成
→ 定义内网 V1 上线

内网 V1 已上线
→ 按 Production Backlog 风险/价值排序
```

不要只因为 Roadmap 文案写着“已完成”就跳过当前代码、测试、CI 和 Completion Gate 证据。
