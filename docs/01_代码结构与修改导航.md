# AIMA_UGC 代码结构与修改导航

本文给准备真正修改代码的人使用，回答：**业务上想改什么，应该从哪个 Owner/文件开始看，哪些边界不要越过，改完验证什么。**

建议顺序：

```text
根 AGENTS.md
→ docs/README.md
→ 本文
→ 相关 Blueprint / 模块 README / Operations / Appendix
→ 当前代码 / Contract / Migration / tests
```

只有任务确实涉及尚未完成的生产目标时，才需要进入 [`docs/roadmap/`](roadmap/)；不要让历史 Stage 决定当前修改面。

- API：[`backend/src/aima_ugc/entrypoints/api_main.py`](../backend/src/aima_ugc/entrypoints/api_main.py) → [`backend/src/aima_ugc/bootstrap/api.py`](../backend/src/aima_ugc/bootstrap/api.py)；
- Worker：[`backend/src/aima_ugc/entrypoints/worker_main.py`](../backend/src/aima_ugc/entrypoints/worker_main.py) → [`backend/src/aima_ugc/bootstrap/worker.py`](../backend/src/aima_ugc/bootstrap/worker.py)；

## 4. TikHub 内容入库链

→ Collection Run / Scope
→ Provider Operation
→ Provider Request / Attempt
→ Raw Artifact
→ Candidate
→ Mapper
→ Canonical
→ Relevance / Decision
→ ContentIngestionService
→ PostgreSQL Content Owner

## 5. 文件导入与历史迁移

当前页面只有一个“导入数据”业务入口：本地选择和批准服务器目录形成不可变 Source Artifact 后，共用 Data Import Campaign、预检、Chunk、Job、进度、取消、重试和逐行账本。

来源与写入策略是两维：

```text
source_kind: local_upload / server_path
ingestion_policy: standard_observation / historical_fill_only
```

修改这条链时，先看 [`docs/operations/02_4000万历史迁移与Analysis Run运行手册.md`](operations/02_4000万历史迁移与Analysis%20Run运行手册.md) 和 [`docs/blueprint/07_技术决策与实施门禁.md`](blueprint/07_技术决策与实施门禁.md)。Historical Fill-Only 不能被前端或临时 SQL 重写。

## 6. AI Analysis

正式链：

```text
用户创建 Analysis Run / 兼容 Request
→ 冻结 Content Version + Analysis identity
→ Planner
→ 有界 Shard Job
→ Analysis Worker
→ LLM Adapter
→ Runtime Taxonomy Validation
→ PostgreSQL Analysis Result
→ Query current/stale/pending + 人工相关性覆盖
```

运行时完整 Scheme 事实来自数据库唯一 active Analysis Scheme；仓库 Prompt 只承担 bootstrap/灾备基线。前端分类项从后端 Taxonomy Contract 获取，不维护第二套枚举。

详细实现见 [`backend/src/aima_ugc/modules/analysis/README.md`](../backend/src/aima_ugc/modules/analysis/README.md) 和 [`docs/appendix/07_AI舆情打标与分析实现.md`](appendix/07_AI舆情打标与分析实现.md)。

## 9. 验证怎么选

按影响面从最小相关层开始：

```text
纯领域逻辑 → Unit
Contract → Contract/API + generated consistency
数据库语义 → PostgreSQL Integration
前端交互 → Vue Unit/Mock Browser
真实跨层业务闭环 → Full-stack
部署/Release → Runtime/Release Workflow + 对应实机门禁
```

完整说明见 [`docs/04_测试与调试说明.md`](04_测试与调试说明.md)。Mock Browser 测试用于快速交互回归，不替代 Browser → Vue → FastAPI → PostgreSQL/Worker → Vue 的真实业务链证明。

## 10. 不要做的事

- 不从旧 Stage/历史聊天猜当前实现；
- 不手改 generated client；
- 不改历史 Migration；
- 不绕过表 Owner；
- 不新建第二套任务队列/数据库/Provider Mapper；
- 不因为页面方便把后端业务状态机复制到 Vue；
- 不把候选未来功能顺手写进 Roadmap；
- 不为“目录更漂亮”做与当前任务无关的大规模重命名。
