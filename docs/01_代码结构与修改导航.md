# AIMA_UGC 代码结构与修改导航

这篇文档给“准备真正改代码的人”使用。

它不重复 Blueprint，也不复制完整 Schema/Contract，而是回答：

> 我知道业务上想改什么，但应该从哪个文件开始看？改哪些层？哪些地方不能动？改完跑什么测试？

第一次接手项目建议顺序：

```text
AGENTS.md
→ docs/blueprint/README.md
→ docs/blueprint/07_技术决策与实施门禁.md
→ docs/roadmap/02_生产上线实施路线.md
→ 本文
→ 当前模块 README / Appendix / Contract / Migration / Test
```

# 1. 先看整个代码地图

后端：

```text
backend/src/aima_ugc/
├─ entrypoints/   # API / Worker / Scheduler / Migration 进程启动
├─ bootstrap/     # 真实依赖装配、跨 Owner 事务编排
├─ modules/       # 领域规则、状态机、Service、表 Owner
├─ adapters/      # TikHub、LLM、PostgreSQL、文件存储等外部实现
```

```text

├─ app/           # Router / Layout

├─ generated/     # OpenAPI 生成 Client，禁止手改
├─ shared/        # 真正跨 Feature 的公共能力
└─ views/         # 当前只保留少量顶层兼容 View
```

数据库：


历史入口复用 Mapper/Canonical/Artifact/Job/Content Owner，但使用 Campaign 全预检、低优先级 Chunk、Fill-Only 和逐行账本。完整运行手册见 [`appendix/14_4000万历史迁移与Analysis Run运行手册.md`](appendix/14_4000万历史迁移与Analysis Run运行手册.md)。

# 11. PostgreSQL 直接排障

先看：

[`appendix/01_PostgreSQL查询与调试实战.md`](appendix/01_PostgreSQL查询与调试实战.md)

重要原则：

```text
SELECT / EXPLAIN / introspection
→ 可以作为调试手段

INSERT / UPDATE / DELETE 业务表
→ 优先不用

```

因为直接 SQL 容易绕过：

- 幂等；
- Fencing；
- Version/Metric；
- 来源链；
- Audit；
- 下游 Job。

